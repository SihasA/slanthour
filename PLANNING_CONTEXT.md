# Slant Hour — Project Context

## What this is

**Slant Hour** is a photography portfolio hosting platform built from scratch as a passion project. It started as one person's portfolio (mine — Sihas Abeywickrama) and is being designed from the ground up to eventually host other photographers under a shared brand and aesthetic.

The name comes from the "slant hour" — the quality of light in the late afternoon. The platform sits at `slanthour.com`.

## Technical stack

| Layer | Tech |
|---|---|
| Frontend | Pure HTML/CSS/JS — no frameworks, no build step |
| Hosting | Vercel (free tier) |
| Deployment | GitHub → Vercel (auto-deploy on push) |
| DNS | Cloudflare (DNS-only, no proxy — important for Vercel SSL) |
| Image compression | macOS `sips` (compressed from raw Fujifilm files ~30MB to ~500KB–1.9MB) |
| Photo management | `scan.js` (Node script) scans `images/` folder, writes `photos.json`; HTML fetches JSON at runtime |

### Repos
- `github.com/SihasA/slanthour` — the main deployment repo (hub + all portfolios live here)
- `github.com/SihasA/sihas-portfolio` — standalone copy of just my portfolio (kept in sync manually)

### File structure
```
slanthour/
├── index.html                        ← Hub landing page
├── vercel.json                       ← Routing config
├── scan.js                           ← Photo scanner (run: node scan.js)
└── sihas-abeywickrama/
    ├── index.html                    ← Portfolio page
    ├── photos.json                   ← Generated by scan.js
    └── images/
        ├── banner/banner.jpg         ← Hero banner image
        └── XT5Album1 1.jpg ...       ← 15 compressed photos
```

### How photo management works
1. Drop new images into `sihas-abeywickrama/images/`
2. Run `node scan.js` from the `slanthour/` root — this regenerates `photos.json`
3. `git add . && git commit -m "Add photos" && git push` — Vercel auto-deploys

### Adding a new photographer (current manual process)
1. Create `slanthour/[photographer-name]/` subfolder
2. Copy `sihas-abeywickrama/` structure into it, update the HTML (name, bio, contact)
3. Drop their compressed images into `[photographer-name]/images/`
4. Run `scan.js` (needs updating to support multiple photographers, or run per-folder)
5. Add their card to `index.html` on the hub page
6. Update `vercel.json` with new rewrite rules for their path
7. Push

## The vision / what I'm planning

**Short term:** Get the portfolio genuinely finished (all photos, good ordering, maybe some caption/series context).

**Medium term:** Invite 2–4 other photographers to have portfolios on Slant Hour. Manual onboarding is fine at this scale. The brand should feel like a curated collective, not a generic host.

**Long term:** Turn it into a real hosting platform — photographers pay a small monthly fee for a beautiful, minimal portfolio under the Slant Hour brand. The differentiator vs Format/Squarespace/Pixieset is aesthetic curation and an invitation-only feel. Not everyone gets in.

### Key open questions for planning
1. **Curation model** — invitation only? Application-based? What are the criteria?
2. **Pricing** — what's the right price point that feels fair but also signals quality?
3. **Branding** — does each photographer's page feel like "their" page, or does it feel like "a Slant Hour page"? How much visual consistency across portfolios?
4. **Platform vs service** — do I want to automate self-service eventually, or keep it as a high-touch service (I set up every portfolio)?
5. **Series/albums** — should the grid eventually support grouping photos into series, or stay flat?
6. **Prints** — is selling prints (my own or others') part of the business model?
7. **Name** — does "Slant Hour" make sense as a brand for a multi-photographer collective?

## Constraints / things to keep in mind

- Everything is static HTML — no database, no server, no auth. Any feature that requires "accounts" or "dynamic content" would be a significant architectural shift.
- The current setup is extremely cheap to run (Vercel free + GitHub free + Cloudflare free).
- I'm not a professional developer — I can edit HTML/CSS/JS and run terminal commands, but I'm not building React apps from scratch.
- This is a side project alongside other work. Realistic pace: evenings and weekends.
- The aesthetic is the product. Any changes need to feel intentional and editorial, not SaaS-generic.
